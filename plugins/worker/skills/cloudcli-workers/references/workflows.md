# 协作案例与模板

按当前任务选择相关案例。Worker 数量取决于独立交付物、工作量和协调成本，以下编号不是固定角色。
主代理负责方案取舍、调度、review、集成与最终验收；Worker 承担执行和局部验证。

## 独立功能并行

例如两个功能已有独立入口和确定接口：

- W1 交付功能 A 的实现与局部验证；W2 交付功能 B 的实现与局部验证。
- 在计划中写明各自 cwd、基线、修改范围和验收条件；共享目录时写入范围不重叠，独立 worktree 时记录各自基线。
- 两项均无未满足的依赖时并行派发。返回后主代理分别检查 diff 和验证证据，记录验收结论。
- 需要集成验证或修复时，指定已有或后续 Worker 执行；主代理确认集成产物已经进入其工作区，再进行最终验收。

## 共享接口先行

例如前后端都依赖一个新增接口：

- W1 同时负责最小接口契约及后端实现，先用一个阶段交付契约；W2 负责前端实现。
- 计划将“接口契约”和“后端实现”记录为两个交付项，可关联同一 Worker 的不同 Run；W2 仅依赖已验收的契约。
- 主代理 review 契约，将所需产物集成到下游工作区或基线，并在计划中记录实际位置。仅收到“接口已完成”的报告还不足以启动 W2。
- 契约已进入 W2 的 cwd 后，续接 W1 完成后端，同时派发 W2 完成前端；两者的修改范围和局部验收分别明确。
- 集成验证交给指定 Worker，主代理核对最终证据。过程中若需改变契约，先记录影响并由主代理确定调整，再更新依赖和交接。

## 不确定问题先只读调研

例如尚未定位失败原因或确认某个接口是否可复用：

- 调研任务只回答明确问题，给出相关入口、可用环境、需要返回的证据，使用 `writePaths: []`。
- 返回事实、复现条件、可选方案与未确定事项；普通局部问题在范围内自行调查，改变任务范围的决定交回主代理。
- 主代理根据证据确定实现方案和验收条件，更新计划，再以明确的写入范围启动实现 Worker。
- 只读 Worker 的声明范围不因补充提示词扩大；不要用续接把原只读任务变成写入任务。

## 计划记录

通过 `worker_context.plan` 读取；首次为 `null`。用 `worker_plan_save({ content })` 提交完整 Markdown。
新目标按章节追加，已完成目标保留简短结论和关键证据。保存不会触发派发、验收或取消。

可以使用下面的形式，按任务合并或缩短字段：

~~~markdown
# 当前目标：具体交付结果

## W1：交付物
- 依赖：无；或指定前置任务及需要的产物。
- 工作区与范围：cwd、基线、允许修改的路径。
- 验收：可以观察或验证的条件。
- 关联：实际 workerId / runId，未派发时明确注明。
- 进度与结论：待执行、执行中、待验收、需返工、已验收或阻塞说明。
- 证据：检查命令及结果，必要时附文件或日志位置。
- 交接：产物位置；下游 cwd 是否已有该产物，以及确认依据。

## 已完成目标
- 简短结论、必要证据和关联 Worker/Run。
~~~

依赖就绪需同时满足主会话验收和产物交接。计划中的进度仅作记录，恢复上下文后须与实际运行状态核对；
日志到期后计划仍保留，但不能据此假定旧 Worker 仍能续接。

## 派发提示词

~~~text
目标：本次需要交付的可观察结果。
任务角色：仅新建任务时按主要交付物选择单一 taskRole，不按提示词关键词猜测；续接沿用原类型，不传 taskRole。
已知背景：相关入口、已确认事实、已有决定和必须沿用的约定。
工作范围：cwd、基线、允许修改的路径。
依赖：需要哪些产物，以及它们在当前工作区的位置。
验收：用哪些行为或检查证明完成。
停止条件：出现哪些范围、契约或依赖问题时返回具体缺口。
执行预算：本轮交付与命令预算；长命令后台执行，单次同步等待不超过 60 秒。
返回内容：改动摘要、逐项验收证据、未完成项和下游可用产物。
~~~

保留主 skill 中的执行边界和超时要求。只读任务使用空写入范围；模板中的已知信息直接填入，
不要让 Worker 再次调查主代理已经确认的内容。

## 结果与返工

~~~text
已完成：改动摘要及涉及文件。
验收结果：逐项说明通过、未通过或未验证，以及原因。
验证证据：实际运行的命令与结果，必要时附日志位置。
未完成或阻塞：具体缺口、已验证事实和需要主代理决定的事项。
下游产物：接口、文件、基线或其他明确位置。
~~~

默认直接返回文本，长报告需要时再附文件。主代理检查实际 diff 和证据后才记录验收通过。
返工提示写清失败条件、应保留的结果、下一次交付和验证要求；运行尚未停止时遵循原有取消确认流程，
然后续接原 Worker，并把新的 Run 标识与处理结果写回计划。
