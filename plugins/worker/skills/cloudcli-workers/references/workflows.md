# 协作案例与模板

按需选用，Worker 数量由独立交付物和协调成本决定。中、大方案先完成方案审核，再放行受审实现。

## 独立功能并行

功能 A、B 已有独立入口和确定接口：W1、W2 分别实现与局部验证，写明 cwd、基线、范围和验收条件。共享目录写入不重叠，依赖就绪后并行；主代理分别核对 diff 和证据。集成验证或修复仍指定 Worker，先确认产物已进入其工作区。

## 共享接口先行

前后端依赖新增接口：W1 负责最小契约与后端，W2 负责前端。契约和后端实现分阶段记录，可关联同一 Worker 的不同 Run。主代理验收契约并交接到 W2 的 cwd/基线后，续接 W1 完成后端，同时派发 W2；不必等待后端全部完成。契约调整由主代理决定并更新依赖，集成验证交给指定 Worker。

## 不确定问题先只读调研

给出明确问题、入口、环境和证据要求，使用 `writePaths: []`。Worker 返回事实、复现条件、选项与缺口；主代理确定方案与验收后，新建具有明确写入范围的实现任务，不把只读 Worker 续接为写入任务。

## 计划记录

从 `worker_context.plan` 读取（首次为 `null`），用 `worker_plan_save({ content })` 保存完整文档。字段可按任务缩短，新目标追加，完成项留结论和证据：

~~~markdown
# 当前目标：具体交付结果

## 方案审核
- 规模与依据：小/中/大；需要/免审。中、大方案必审。
- 需要时：workerId/runId、受审方案位置或版本、意见处理及主代理验收结论；实现依赖该结论。

## W1：交付物
- 依赖：前置任务及所需产物，或无。
- 工作区与范围：cwd、基线、读写路径。
- 验收：可观察或验证的条件。
- 关联与进度：workerId/runId 或未派发；执行中/待验收/返工/已验收/阻塞。
- 证据与交接：命令及结果、产物位置、已进入下游 cwd/基线的确认依据。

## 已完成目标
- 简短结论、必要证据及 Worker/Run。
~~~

## 派发与返工

~~~text
目标：本轮交付结果。
角色：新建按主要交付物选 taskRole；续接不传。
背景与约束：入口、已确认事实、已有决定。
范围与依赖：cwd、基线、writePaths、前置产物位置。
验收与停止：检查项、中途交付、范围/契约/依赖问题的停止条件。
预算：timeoutSeconds；长命令后台执行，同步等待不超过 60 秒。
返回：改动、逐项验收证据、未完成或阻塞、下游产物位置。
~~~

只读任务 `writePaths: []`，已有事实直接提供。默认返回文本，长报告按需附文件。返工优先续接原 Worker，写明失败条件、保留结果和下一交付；运行未停止时先遵守取消确认流程，接受后更新计划中的 Run。
