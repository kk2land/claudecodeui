# 计划记录、交接模板与案例

按需读取。规则见 SKILL.md，这里只有模板和案例，常规派发不必读。

## 计划记录

字段按任务缩短，新目标追加，完成项留简要结论与证据。

~~~markdown
# 当前目标：具体交付结果

## 计划阶段
- 方案规模：小/中/大。方案审核：需要/免审。一句依据。
- 需要审核时记下 workerId/runId、受审方案位置或版本、意见处理与定稿结论。实施阶段沿用，不为修复或调整新增方案审核。

## W1：交付物
- 依赖：前置任务及所需产物，或无。
- 工作区与范围：cwd、基线、读写路径。
- 验收：可观察或可验证的条件。
- 关联与进度：workerId/runId 或未派发。执行中/待验收/返工/已验收/阻塞。
- 证据与交接：命令及结果、产物位置、产物已进入下游 cwd/基线的依据。

## 已完成目标
- 简短结论、必要证据及 Worker/Run。
~~~

## 派发交接

~~~text
目标：本轮交付结果。
角色：新建按主要交付物选 taskRole。配置只在用户明确选择时传入。
背景与约束：入口、已确认事实、已有决定。
范围与基线：cwd、基线、writePaths、前置产物位置。
验收与停止：检查项、中途交付、范围/契约/依赖问题的停止条件。
限制：不递归派发，不 commit/merge/push，不清理 worktree，其他限制按本批任务写明。
预算：长命令后台执行，单次同步等待不超过 60 秒。超时但进程未退出时停止本任务进程并保留日志。
返回：改动、逐项验收证据（路径与验证结果）、未完成或阻塞、下游产物位置。
~~~

只读任务 `writePaths: []`。已有事实直接提供，长报告按需附文件。返工优先续接原 Worker，写明失败条件、保留结果和下一交付。运行未停止时先完成取消确认，接受后更新计划中的 Run。

## 案例

- 独立功能并行：两个功能各有入口和确定接口时，分派 W1、W2 分别实现与局部验证，写入路径不重叠。主代理分别核对 diff 与证据，集成验证仍交给指定 Worker。
- 共享接口先行：W1 出最小契约并实现后端，主代理验收契约后交接到 W2 的 cwd/基线再放行前端。不必等后端全部完成，契约调整由主代理决定并更新依赖。
- 未知问题先只读：用 `taskRole: "plan_research"`、`writePaths: []` 返回事实、复现条件、选项与缺口。主代理定方案后新建有写入范围的任务，不把只读 Worker 续接为写入任务。
