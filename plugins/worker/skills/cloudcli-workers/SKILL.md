# CloudCLI Worker 协调

正常门槛是全局入口 `AGENTS.md` 的 CloudCLI Workers 引用块及其指向的 `CLOUDCLI-WORKERS.md`，分流、回退与角色要求以那里为准，本文只写通过门槛后的做法。

只安装了本 skill 而没有该引用块时按以下短规则执行。不把补装脚本当作阻塞。

- 用户明确指定的执行方式和委派范围优先。否则默认委派 Worker。主代理直接处理只限根据已有信息回答、一次明确查询即可确认，或在已知位置按明确指示做可直接核对的机械修改。
- 技能被禁用、未启用，或 MCP 未连接、缺所需工具时，跳过本 skill，用普通工具直接完成原任务，不要求先配置 MCP。
- 已进入 Worker 流程后调用持续失败时，报告事实、原始错误与已尝试调用，不接管执行子任务，也不绕过 MCP 调用底层执行器。
- 子 Worker 只做本次派发的任务，不递归派发、不 commit/merge/push、不清理 worktree。

## 计划与依赖

- 决定委派后先调用一次 `worker_context`，同轮复用，范围变化或恢复上下文时刷新。仅看活动状态可传 `view: "compact"`。派发前确需并发、配置（`settings.configs`/`defaultConfigId`、兼容投影 `settings.enabled`/`roles`）、核对既有 Worker 的 `writePaths`，或恢复未掌握全文的计划时省略 `view` 读全量，并核对计划与实际状态。
- 局部改动只有一个可独立验收的交付物时，用一个 Worker 和一条计划记录。复杂改动先列出可独立验收的交付，逐项写明最小写入范围、前置产物和验收条件。共享接口各指定一位负责人。
- 共用工作区并行时，确认各项读取的输入稳定，写入、构建和测试互不干扰。需要隔离时，可从包含已验收前置产物的基线开独立 `worktree`。共享接口能先确定时，先交付最小数据约定和可用样例，其余工作可用模拟数据或 fixture 并行。重叠改动集中交给一人。
- 依赖已就绪且彼此独立的任务同轮提交。达到并发上限时，调度器会把已提交的任务排队。
- 复杂任务采用单 Worker 时，计划简述比较过的拆法及实际原因，例如具体依赖或协调成本高于收益。跨 Worker 联调只等待所需交付完成局部验收并进入集成工作区。指定 Worker 执行联调验证，主代理做最终验收。
- 每个父会话与项目维护完整 Markdown 计划，记录目标、方案规模及审核依据、任务与依赖、cwd/基线/读写范围、验收条件、worker/run 标识、进度与证据、产物位置。用 `worker_plan_save({ content })` 整段替换保存，仅在调整、派发、验收、阻塞或返工时保存。保存只记录，不触发执行或验收。计划模式只形成方案，保存和派发都遵守当前会话模式与授权，仅启动已就绪任务。Worker 内要有任务所需工具与环境。新目标追加，完成项保留简短结论与证据。
- 依赖须经主代理验收，且产物已进入下游 cwd 或 `baseRef` 才放行。验收时记录产物路径、确切 commit/baseRef（或已确认的下游 cwd 版本）与验证结果，确认下游可读后再派发。交接为每项依赖写清简短产物引用，可多项。独立 worktree 不自动同步，MCP 排队没有 `dependsOn`。
- 并行任务出现需用户决定的事项时，在计划的可选“待决定”短节记录问题、建议和受影响 Worker/Run；合并向用户提问，答案只用于续接相关原 Worker，独立任务照常推进。模板与示例见 [计划记录与交接模板](references/workflows.md)。

## 方案审核

- 只用于计划阶段形成的整体方案，不是每次改动的前置。在已授权的计划阶段、方案定稿前，向只读 `plan_review`（`writePaths: []`）提供方案、基线、约束和验收条件。中、大整体方案需要审核，实现和验收明确的小方案可免审。审核工具不可用时如实记录，按门槛回退，不把审核推迟为实施阶段的新门槛。
- 审核交付须给出明确结论。发现问题时说明原因，并给出具体、可执行的调整建议。主代理在定稿时处理意见并记录结论，进入实施后复用已有结论。
- 进入实施后，修复、需求调整、契约调整和集成问题由主代理协调开发、测试与代码审核，不补审方案。`plan_review` 审方案，`code_review` 审已完成代码与测试。用户明确指定的执行方式优先。规模判定或角色含义有疑问时读 [角色与配置路由](references/routing.md)。

## 派发与续接

- 先保存计划再派发，接受后回填 worker/run 标识。交接写清目标、范围与基线、验收、停止条件，以及本次任务的全局执行限制。已有事实直接提供，不要求 Worker 重查。模板已给出具体写法，需要时读 [计划记录与交接模板](references/workflows.md)。逐角色证据见模板；有答案续接原 Worker，长详情按需读取。
- 每次启动/续接用新 `requestId`，仅同一操作和载荷重试时复用。不重复派发同一目标。新建任务按主要交付物标注单一 `taskRole`。带角色的新建使用内置职责和回报规则，交接不必重复。省略角色时可在交接中显式要求首句结论。`writePaths` 相对 cwd，只读为 `[]`。
- `worker_start` 显式选 `workspace.mode`。`existing` 写入不重叠，`worktree` 隔离并可指定 `baseRef`。脏源默认拒绝，仅已授权、确认不依赖未提交改动且记录基线后用 `allowDirtySource: true`。
- `worker_resume` 用原 workerId、cwd、home 和原生会话，不传 `taskRole`，模型/effort 沿用原 run 除非用户指定覆盖。只读任务不能续接为写入任务。其余范围或契约变化由主代理决定。续接只交接变化的部分。
- 配置只在用户明确选择时传入，省略时按已启用配置路由。`type` 只是引擎过滤条件，不能替代配置。角色含义或配置选择有疑问时读 [角色与配置路由](references/routing.md)。
- start 和 resume 默认都省略 `timeoutSeconds`，由所选配置决定硬超时。长任务按可验收阶段续接。仅当用户明确指定本轮硬超时（给出秒数或时长）时传秒数。用户明确要求本轮取消硬超时才传 `null`。预计时长、要求快审、等待窗口、软提醒都沿用默认硬超时。覆盖与 `null` 语义见 [角色与配置路由](references/routing.md)。提示词给出命令预算，长命令后台执行，单次同步等待不超过 60 秒。测试已报超时而进程未退出时，停止本任务自己的进程并保留日志。

## 视图与回包

- 常规调用在工具 schema 提供 `view` 时传 `view: "compact"`，省略即原完整形状。start/resume 紧凑回 `workerId` 与 `runId`，即实际接受的运行。`worker_get` 紧凑仍有 Worker 记录和完整当前 run，只省略历史 runs 与已投递通知。
- 需要计划全文、配置、历史 runs 或已投递通知时用原调用，按需重取全文。手上没有最新计划全文又要续写时先取完整 `worker_context`，再整份写回计划并保留未完成任务与依赖。
- 旧调用仍用原参数和同一 `requestId`，不因视图改动请求。视图不可用或缺字段时按原调用重取。

## 运行与验收

- start/resume 接受即返回，可能排队。接受后继续推进任何未完成的独立工作。只剩等待时发简短状态并立即结束当前回合。Worker 在后台继续，下一次检查由 Worker 通知唤醒，不占住回合。不用原生 `clock.sleep`、shell `sleep`，也不反复 `worker_list`/`worker_get`/`worker_logs` 轮询等结果。新任务不自动 steer/取消原 Worker。
- 需要查询时用 `worker_list`/`worker_get`，复用响应。按 `notifications[].id` 批量 `worker_ack`，重试复用 ID。`completed` 和 ack 都不代表验收。状态可单次检查，通知到达后的验收照常。`worker_wait` 仅限用户明确要求当前回合同步等待时的单次调用，最长 25 秒，不循环轮询保活。
- 首次预算提醒默认 600 秒或 20 步，已投递后每 600 秒再提醒，未投递不叠加。提醒先作初筛，只有需核对当前 run 或产出时才 `worker_get`；是否干预仍看实际产出。`running`、步数和进程存活不算进展。有新有效产出就等下次自动提醒，软提醒不自动取消。
- 验收核对实际 diff 和验证结果，证据用路径与结论表示，不采信自述摘要。按 run/stream/cursor 增量读 `worker_logs`，每次小页；查最近错误可按需 `tail: true` 读末尾，再用返回的 `nextCursor` 续读。日志不改变执行边界。集成后完成必要的最终验收。结论、证据与交接写回计划，未验证项明确标注，旧计划不证明 Worker 可续接。
- 仅因新改动、失败或未决问题重跑。同一失败已在未修改基线复现时，记录限制并继续剩余交付，不重复完整测试。
- 向用户报告改动、验证结果、阻塞项和 worker/run 标识。

## 纠偏与停止

- 偏离方向、持续无进展或重复无效工作时，对原 workerId 用 `worker_cancel(pause: false)`，确认停止后 `worker_resume` 说明偏差、保留结果、下一交付及检查/停止条件。
- 反复无进展或 MCP 持续失败时，报告事实、原始错误与已尝试调用，停止派发。无新证据不重试。
- 用户或宿主 Stop 后，等待明确继续再续接。unknown 或取消未确认不得续接，核实原生会话和进程已停止后才用 `worker_recover(notes, confirmedStopped: true)` 恢复，不重跑。
- 普通问题在 Worker 范围内解决。改变范围、契约、验收或缺少依赖时返回事实与缺口，由主代理决定并更新计划。返工优先续接原 Worker。

## 合并与清理

主代理 review 和必要验证后按授权合并。插件创建的 worktree 合并后必须 `worker_cleanup`，须工作区干净、Worker 已停止且无其他任务占用。保留分支、原生会话和日志。清理后不可 resume，后续用 `worker_start` 新建。
